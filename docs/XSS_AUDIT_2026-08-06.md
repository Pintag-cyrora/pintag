# XSS Audit — admin HTML rendering (2026-08-06)

Scope: every `innerHTML`/template-literal sink on the admin-privileged
surfaces (they run in the highest-privilege session, so a stored-XSS payload
in listing data would execute with admin rights). Public pages were counted
but are lower-risk (no privileged session to steal).

## Sink inventory

| File | `innerHTML` sinks | Escaper available | Status |
|---|---|---|---|
| `admin.html` | 53 | `esc()` (admin.html:973 — escapes `& < > " '`) | ✅ data interpolations escaped; 2 fixed this audit |
| `gallery-recovery.html` | 34 | `esc()` (line 111) | ✅ escaped throughout; escaper hardened to include `'` this audit |
| `intelligence.js` | 23 | `esc()` (line ~69) | ✅ escaped |
| `analytics.js` | 10 | `esc()` | ✅ escaped (remaining raw interpolations are computed numbers/class names) |
| `listings.html` / `listing.html` / `agents.html` / `index.html` | 9 / 10 / 5 / 2 | per-page escapers | public pages; same pattern |
| `components.js` / `charts.js` | 9 / 9 | static markup / numeric data | ✅ no external data interpolated |

## Method

1. `grep -c innerHTML` per file (counts above).
2. Heuristic sweep for `${...}` interpolations on lines without `esc(`,
   filtered to data-shaped expressions (`p.`, `owner.`, `${url}`, `${name}`,
   `${title}` …).
3. Manual review of every hit.

## Findings & fixes (this audit)

| Location | Issue | Fix |
|---|---|---|
| `admin.html` `refreshImageGrid()` (~3726) | `<img src="${url}">` interpolated the raw image URL into an attribute; a URL containing `"` could break out and inject attributes (e.g. `onerror`). Sources are own-storage URLs (server-generated names), so exploitation required admin self-action — but the sink was unsafe. | `src="${esc(url)}"` |
| `admin.html` import image grid (~3993) | Same pattern. | `src="${esc(url)}"` |
| `gallery-recovery.html` `esc()` | Did not escape `'` — safe in the file's current double-quoted-attribute usage, but one future single-quoted attribute away from a gap. | `'` added to the escape map |

## Reviewed and intentionally left as-is

- `admin.html:1616/1626` — `<option>` lists built from the static
  `FURNISHED_OPTIONS` / `ORIENTATION_OPTIONS` constants (hardcoded, no
  external data).
- `admin.html:1074-1078` — amenity checkboxes from the static registry in
  `amenities.js`.
- `admin.html renderOwnerPhoneCell()` (~2850) — looks unescaped at the sink
  but every value is escaped/sanitized upstream (`phone`/`name` via `esc()`,
  `wa` via digits-only `_ownerWaDigits()`).
- `analytics.js:163` — `d.dir`/`d.pct` are computed class names and numbers.

## The rule going forward

- Every interpolation of ANY value that ever touched the database, an import,
  or user input goes through the page's `esc()` — **at the sink**, even when
  it "should be safe upstream."
- `esc()` must escape all five of `& < > " '`.
- URL-shaped values are escaped like any other value when interpolated into
  attributes; values placed into inline `onclick='...('${v}')'` handlers
  additionally need their quote-stripping (`safeUrl` pattern) — prefer
  `data-*` attributes + `addEventListener` for new code.
- New raw-HTML sinks require a reviewed reason; the default for new code is
  `textContent` / `createElement`.

Residual risk after this audit: **low** — remaining sinks interpolate either
escaped values or static constants. The structural follow-up (L2, not L1) is
reducing sink COUNT by moving hot paths to `createElement`/`textContent`,
which removes the "one future oversight" class entirely.
